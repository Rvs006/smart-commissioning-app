# v0.1.63 field acceptance checklist

- [ ] Record the approved site and scan authorization in the private record.
- [ ] Use the v0.1.63 unified portable EXE on a test machine. Built-in TCP
      connect is the default; use a separately installed Nmap only after
      explicit approval.
- [ ] Open Brief and confirm the protected dry-preview, sealing, approval,
      authorization, live-run, terminal evidence, failure, and retry guidance.
- [ ] Open Learning and follow the numbered IP discovery and retry procedures.
- [ ] Confirm every scan status and troubleshooting entry is readable at
      desktop and mobile widths, and click every interactive help control.
- [ ] Confirm Nmap guidance states that the EXE does not bundle, install, or
      download Nmap or Npcap and that v0.1.49 retry/run isolation is unrelated.
- [ ] Confirm MQTT guidance leaves Payload type blank where appropriate, uses
      `#` only in a topic or topic-filter field, and exposes no private template.
- [ ] Complete an IP dry run and its approved sealed live run. Wait for
      confirmed terminal evidence and inspect Results.
- [ ] Confirm the portable visible version and `/api/v1/health` version both
      identify v0.1.63.
- [ ] Perform separately approved IP, BACnet, and MQTT site tests and
      retain private evidence. No BACnet write capability is provided.
- [ ] While a scan or UDMI capture is running, open Run History and the import
      and UDMI pages and confirm none of them fails with `database is locked`.
- [ ] Run BACnet discovery against a device that cannot segment its object list
      and confirm its objects are listed; if the row reports
      `object_list_indexed_read`, check `entries_read` against `entries_total`.
- [ ] On a fresh install, confirm Configuration shows "Not saved yet" under the
      Source Interface until Save Configuration, and that a UDMI run shorter
      than the largest Expected reporting interval shows the warning.
- [ ] Complete an explicitly approved UDMI validation run. Wait for confirmed
      terminal evidence, then retain its run ID and evidence-set ID in the
      private field evidence store.
- [ ] Generate both the condensed client report and the technical report from
      that exact UDMI validation run and evidence set. Verify the technical
      payload-manifest hashes and the expected redaction state, then record the
      SHA-256 hash of each report in the final record.
- [ ] Import a register with one asset whose Payload applicability is
      `state, metadata` and whose device also publishes pointset. With
      Ignore Payloads Outside Applicability Disabled, run UDMI validation and confirm
      the "not approved for this asset" issue appears. Set it to Enabled, Save,
      run again, and confirm that issue and every pointset finding for that
      asset are gone while state and metadata are still validated.
- [ ] Record the exact application commit, portable or image hash, run ID,
      evidence-set ID, condensed client report SHA-256, and technical report
      SHA-256, then record acceptance-owner sign-off.

All rows remain open until recorded in the private field evidence store.
