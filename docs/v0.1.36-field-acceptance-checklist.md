# v0.1.36 field acceptance checklist

Use the Smart Commissioning App and the append-only MQTT evidence collector over
the same approved topic scope. The scale run proves capture volume. A separate
run must cover the slowest expected payload cadence. This checklist does not
declare field acceptance until every required run and reconciliation passes.

## Preparation

| Record | Value |
| --- | --- |
| Source register file and SHA-256 | |
| Application version and commit | |
| Machine and operating system | |
| Broker product and version | |
| Approved topic scope | |
| Start time and time zone | |
| Engineer initials | |

- [ ] Use the exact unchanged register and record its expected asset count.
- [ ] Record the application subscription scope and calculated topic count.
- [ ] Enable asset-topic discovery only for the reconciliation run. Use the
  bounded register scope unless the wider capture has explicit approval.
- [ ] Record the discovery scope and the per-asset topic evidence limit.
- [ ] Start scripts/capture_mqtt_evidence.py with a new output filename.
- [ ] Supply credentials through the approved secret manager, a process-scoped
  environment variable, or the hidden prompt. Never place a password in source,
  command arguments, reports, or evidence archives.

## Console and topic evidence

| Evidence | Recorded value |
| --- | --- |
| Expected-topic observed | |
| Alternate-topic observed | |
| No matching topic observed | |
| Waiting-for-evidence reason, if shown | |
| UI/run-state samples | |

- [ ] Compare expected-topic, alternate-topic, and no-matching-topic console
  values with the exported run-summary and topic-discovery evidence.
- [ ] Treat the UI/run-state heartbeat as display sampling only; it is not
  broker-message evidence or a message rate.
- [ ] Treat Waiting for evidence as unavailable information, not a zero count.
- [ ] For every asset absent from the app observation count, record raw topic,
  receive time, expected register topic, and application status.
- [ ] Confirm whether each raw topic was in the approved subscription scope.
- [ ] Mark an in-scope raw message that the app did not associate as a defect;
  do not relabel it as a successful observation.
- [ ] Keep unexpected publishers visible but separate from registered-asset
  compliance totals.

## Cadence run and decision

- [ ] Run for at least the longest expected cadence. Use 24 hours when a
  required payload is expected daily.
- [ ] Record stale, silent, malformed, schema-invalid, wrong-topic, and
  unexpected-publisher findings separately.
- [ ] Record SHA-256 values for the source register, JSONL capture, app export,
  PDF, DOCX, XLSX, JSON evidence pack, and combined ZIP.
- [ ] No credential appears in any retained or shared file.
- [ ] Field acceptance is not declared until the scale and longest-cadence runs
  pass.
