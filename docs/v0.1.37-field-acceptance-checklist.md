# v0.1.37 field acceptance checklist

This checklist keeps application acceptance separate from publisher and field
acceptance. A successful report job is not a field pass.

## Frozen contract

| Record | Value |
| --- | --- |
| Canonical register file and SHA-256 | `<REGISTER_FILE> / <REGISTER_SHA256>` |
| Register revision and import identity | `<REGISTER_REVISION> / <IMPORT_ID>` |
| Expected asset count | `752` |
| Approved scope | `<APPROVED_SCOPE>` |
| Application commit | `<40_CHARACTER_COMMIT>` |
| Gate A run ID | `<GATE_A_RUN_ID>` |
| Gate B run ID | `<GATE_B_RUN_ID>` |
| Operator, machine, broker references | `<OPERATOR_REF> / <MACHINE_REF> / <BROKER_REF>` |

Create the sanitized manifest with `scripts/build_v0137_acceptance_manifest.py`.
The manifest records the register hash and references only. Keep the actual
register, credentials, broker commands, and device details in the approved
private field workspace.

Start the independent collector with `--acceptance --manifest <MANIFEST>
--run-id <GATE_RUN_ID>`. The collector rejects incomplete or mismatched
provenance before it connects to the broker.

## Gate A: full-register scale

- [ ] Use the exact 752-row register and one approved, unfiltered scope.
- [ ] Load the pre-run manifest and reject a different register, scope,
  application commit, or import identity.
- [ ] Record paired application and independent append-only evidence with the
  same run ID, register hash, scope, start acknowledgement, end acknowledgement,
  terminal status, and termination reason.
- [ ] Reconcile each registered asset as expected-topic, alternate-topic,
  no-match, or missing. Keep unexpected publishers outside registered metrics.
- [ ] Generate one frozen report set whose title, scope, register identity, and
  run identity match the manifest.
- [ ] Hash every retained artifact and run the credential/prohibited-identifier
  scan over the complete sanitized bundle.

## Gate B: longest cadence

- [ ] Run the complete required cadence, documented as 24 hours when daily
  payloads are authoritative.
- [ ] Pass only with `window_completed=true` and
  `termination_reason=window_elapsed`.
- [ ] Fail explicitly for cancellation, broker interruption, message or
  resource caps, disk failure, truncated JSONL, or any partial evidence.
- [ ] Keep stale, silent, malformed, schema-invalid, wrong-topic,
  alternate-topic, and unexpected results separate.
- [ ] Preserve Gate A evidence and compare final hashes without overwriting it.

## Application gate

- [ ] Validator tests distinguish missing values from received `0` and `false`.
- [ ] State-shaped payloads on metadata topics produce one grouped routing
  diagnostic with raw topic and key evidence.
- [ ] Reports and exports retain the selected run, frozen provenance, and prior
  report after a later error.
- [ ] Reports UI has no obsolete import or run-control panels, and its bounded
  report list, filters, download, retry, and navigation controls work.
- [ ] Indefinite capture is explicit, cancellable, and bounded by backstops.

Field acceptance remains open until both gates pass and the acceptance owner
records approval. No row in this repository claims that the field gates passed.
