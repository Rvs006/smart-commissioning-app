# v0.1.29 field acceptance checklist

Use this checklist with MQTT Explorer open beside the Smart Commissioning App.
The two-hour run proves capture scale. It does not prove payload families whose
expected cadence is longer than two hours.

## v0.1.27 baseline

The supplied 554-asset field export contains 287 observed assets and 267
not-observed assets. The separate topic comparison classifies 465 assets as
topic matches, 18 as mismatches, and 71 as unclassified. Only 284 of the 465
topic-matched assets were observed by the app, leaving a 181-asset correct-topic
gap. The v0.1.27 report itself does not retain a wrong-topic asset list or the
frozen imported register. A fresh v0.1.29 run is required before classifying
that gap or accepting the result.

- [ ] Expected assets equals 554.
- [ ] Observed assets plus not-observed assets equals 554.
- [ ] Every imported asset appears exactly once in that reconciliation.
- [ ] Treat the wrong-topic count as a marked subset of observed registered
  assets, not as a third group added to the 554-asset total.
- [ ] The app's wrong-topic list names every matched register asset and shows
  its system, expected topic, actual topic, payload type, and last-seen time.
- [ ] Wrong-topic assets retain their
  state, metadata, and pointset content-validation results.
- [ ] The XLSX contains `Wrong Topic Assets` and `Annotated Input Register`.
- [ ] The ZIP contains `wrong_topic_assets.json` and
  `annotated_input_register.json`.
- [ ] The annotated register contains exactly 554 source rows in their original
  order. Original columns and values remain unchanged; report annotations are
  appended.
- [ ] For each wrong-topic row, `Topic status` reads `Wrong topic` and `Actual
  topic(s)` agrees with the approved MQTT Explorer comparison.
- [ ] A genuinely silent imported asset stays `Not observed` and is absent from
  the wrong-topic list.
- [ ] Assets visible in MQTT Explorer appear in the app when their exact asset
  identity and topic fall inside the configured scope.
- [ ] An absent payload reads `Not received`.
- [ ] An absent pointset creates no synthetic missing, extra, or misnamed point
  cards.
- [ ] A received empty pointset object, `{}`, is still validated.
