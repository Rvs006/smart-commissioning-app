# v0.1.54 release and test note

Status as of 2026-08-25. v0.1.54 is the latest published release, pinned to
commit `9d90eb8`.

## Internal record

v0.1.54 is published as the Latest release. The release artifacts are bound to
one commit, `9d90eb8`: the signed tag, the GitHub release, the portable EXE, and
all three Docker images (by digest). `9d90eb8` is the release SHA. Main was at
`9d90eb8` when v0.1.54 was cut and moves ahead with later work, including this
note, so do not read `9d90eb8` as main's current position.

What changed in code this cycle was release-gate tooling, not the app. The CI
evidence validator and the secret scanner were hardened: they fail closed on
malformed evidence, catch JSON credentials (including pretty-printed and deeply
nested ones), and reject archives nested past the depth cap. None of that ships
inside the EXE, so the commissioning tool itself behaves the same as v0.1.53.

Cleanup is done. The same-day v0.1.53/54/55 churn is collapsed into one clean
v0.1.54, v0.1.55 is fully removed (release, tag, images), and the Docker images
that were deleted by mistake are rebuilt and live again. The ZIP SHA-256 below
replaces any earlier hash.

## Engineer note (shareable)

v0.1.54 is live as the latest release. It is the portable Windows build, no
install: unzip and run `SmartCommissioningApp.exe`. Read `README_FIRST.txt` in
the bundle first.

Download:

- Release page: https://github.com/Rvs006/smart-commissioning-app/releases/tag/v0.1.54
- Direct ZIP: https://github.com/Rvs006/smart-commissioning-app/releases/download/v0.1.54/Smart_Commissioning_App_Windows_Portable.zip
- Verify after download, ZIP SHA-256:
  `58329CA17883D16D345B165653E665CE778D44442608C6862DE6FC3AE4397425`

Straight answer on what is new in the app: nothing. This release changed only
the CI release-gate tooling (evidence validator and secret scanner), which does
not ship inside the EXE. Functionally it is the same commissioning tool as
v0.1.53. Treat this as an acceptance and regression pass, not new-feature
testing.

Smoke test to run:

- Launch: app starts, picks up a NIC, first screen clean.
- IP discovery: scan a known subnet, confirm devices return.
- BACnet: discover on the selected source interface, browse objects.
- MQTT: connect to a broker, open the live topic tree, confirm A-Z ordering holds.
- UDMI: generate the expected payload views and run a validation.
- Reports: generate a client report and a technical report, confirm both open.
- Advanced tab (IP/BACnet/MQTT): open the embedded scanner panel, confirm reads
  work and a device write asks for confirmation before it runs.
