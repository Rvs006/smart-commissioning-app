# v0.1.30 field acceptance checklist

Use the Smart Commissioning App and the append-only MQTT evidence collector over
the same approved topic scope. The two-hour run proves capture scale. A second
run must cover the slowest expected payload cadence.

- [ ] Use the exact unchanged register and confirm the expected asset count.
- [ ] Record the calculated validation-topic count.
- [ ] Confirm automatic retained-message capacity is at least that count.
- [ ] Start `scripts/capture_mqtt_evidence.py` with a new output filename.
- [ ] Supply credentials through the approved secret manager, a process-scoped
  environment variable, or the hidden prompt. Never place a password in source,
  command arguments, reports, or evidence archives.

- [ ] Expected equals observed plus not observed, with every register asset
  counted once.
- [ ] Compare state, metadata, and pointset independently by exact topic.
- [ ] Wrong-topic assets show expected and actual paths and retain content
  validation results.
- [ ] Unexpected publishers remain visible and are excluded from expected
  compliance totals.
- [ ] An absent payload reads `Not received`; a received empty payload is still
  validated.
- [ ] Any difference between app and JSONL counts is explained by approved topic
  scope, start/end time, QoS, retained delivery, or an evidenced broker event.
