## v0.1.39 implementation evidence

The candidate includes these application changes:

- Shared evidence-set identity across report formats, with renderer, source,
  register-file digest, capture, and run provenance retained in the report
  snapshot. Missing external identity fields remain explicit rather than being
  inferred.
- Explicit cancellation and partial-capture semantics. A cancelled or
  incomplete window cannot satisfy the field-acceptance eligibility predicate.
- Register-driven payload applicability. The validator records unresolved
  applicability as a blocker and does not invent expected payload facets.
- Separate payload timestamp, broker receive timestamp, retained status, and
  cadence status.
- Bounded redacted raw evidence in the validation result and a portable
  technical ZIP area with manifest and JSON Lines records.
- Client and technical report products generated from the same evidence model.
- Expected-versus-observed mismatch markers in the report model, technical
  detail, and workflow UI.
- Explicit optional Floor handling. Room values are not used as Floor.

## What has not been measured

There is no new v0.1.39 field run in the local evidence set. Therefore this
document does not claim a new asset count, payload count, finding count,
cadence result, publisher result, or acceptance score. The next run must use
the approved register, approved applicability matrix, approved topic filters,
and the approved longest cadence.
